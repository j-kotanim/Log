## 2. 議題ごとの詳細

### ① 不具合分析へのAI適用（DVDプロジェクト）
- LLM＋Copilot Studio によりテスト不具合の**原因分析・自動分類**を行う仕組みを検討・試行。
- 分類理由をわかりやすく提示し、再発防止・対応すべき点を提案させる形式。機種名・用語等はナレッジとして登録。
- エージェントがPDFを解析し、不具合概要／分類／分類根拠を出力。
- **成果**
  - 分析観点の**標準化**が進み、担当者によるばらつきが低減。
  - 不具合の捉え方・分類理由をチーム内で共有しやすくなった。
  - 「どの工程で不具合を作り込んだか（設計不良か等）」の意識付けにつながり、工程に応じた処置を考えるきっかけになった。
  - 特定メンバーに集中していた分析ノウハウを、**AIをサポートツール**として使うことで平準化。教育効果が大きい。
- **今後**: 次の課題を「**要求仕様書の作成品質**」に設定。一方通行ではなく対話型フィードバックプロセスでAIと仕様を育てる方式を次プロジェクトから実施予定。

### ② Linux cgroup を活用したリソース保護
- **背景**: 市場でリソース枯渇に起因する機能不全が発生。マルチプロセス環境でファイルシステム使用量の最大負荷が読みにくく、流出に至った。
- **対応**: 総合DVDで**最大負荷条件**を想定した試験を実施し事象を再現。Linux標準の **cgroup** を導入してリソース（CPU／メモリ／ディスクI/O）をグループ単位で制限・優先度制御。
- **適用**: 大量ファイルを扱うプロセスを1つのcgroupにまとめ、メモリ上限を設定。閾値超過時はカーネルが回収する動作を確認。
- **工夫**: 上限到達時に破綻しないよう、閾値の決め方をトライ＆エラーで調整（1〜2ヶ月）。リアルタイムスキャン／レプリケーション／スナップショット／定期スキャン等の多重動作でも問題が出ないことを確認。
- **成果／知見**: 機能開発だけでは解決できない**システム全体の安定化手法**を獲得。市場事象を製品開発にフィードバックする流れを確立。

### ③ 繊維事業部：AI活用とCRA対応

**AI活用**
- QMS活動としてAIコーディングアシスタントを導入。**導入効果のKPI**を今期中に検討・まとめる。
- 適用範囲: パネルコンピュータ開発で**テストコード作成／コードレビュー／不具合調査**に適用開始。
- **LLM選定**: 課金制移行に伴い評価中。軽量モデルはやり直しが頻発し不向き。コンテキスト長超過も課題。現在はトークン消費を抑えて運用、部内で融通しながらテスト継続。レガシーソースへの適用も検証中。

**CRA対応**
- **対象製品**: MSSソリューション、オートワインダー、ボルテックス（生産終了機種含む）、工場内無線コンバータ等。旧世代含めCRA対応が必要。
- **第14条**（脆弱性報告義務）を最優先で対応中。リスク分析（脅威、アタックツリー、SBOM）をコンサル支援で実施。
  - MSSソリューションでコンサルから多数のフィードバック（6月に17件、その後も追加）。意図が不明な指摘は個別相談会で解消予定。
  - 残課題3件を今週中に対応予定。
- **リスク分析結果**
  - インターフェース 114件、資産 71件を洗い出し、対策候補 **73件**を抽出。
  - 内訳: パネルコンピュータ／MSS関連 32件、システム全体 18件、OS変更・運用教育 21件（ゲートウェイPCで保護する13件を含む）。
  - 攻撃の蓋然性（高／中／低）×被害の大きさ、ノウハウ資産性（高／中／低）でリスク判定し優先度付け。
- **主な必要対策**: 連続ログイン失敗時のアカウントロックアウト未実装、ネットワーク監視・通信遮断、制御装置へのプログラム書込みの暗号化・署名、Webアプリのセキュアコーディング、クラウド上の操作ログ取得・監視。
- **第13条**対応: MSSと繊維機械だけでは対策困難なため、顧客ネットワークとの間に**セキュリティ対応ゲートウェイPC（ボックスPC）**を新設しE2E保護する方針。コスト（20数万円）が課題で、セキュアルータ等の代替も継続検討。
- **セキュリティ仕様書**を13項目に整理して作成中。今後、設計・実装フェーズへ。
- **その他**: 全社のセキュアコーディング規約改訂に参画（C/C++、Java、Python、JavaScript対象）。トルコ向け対応も要調査。

### ④ ICC：AI活用とCRA向け暗号ライブラリ検証

**AI活用（ワーキンググループ／若手中心6〜7名）**
- 背景: 小規模製品では担当者1名依存でノウハウが属人化、メンバー間の品質ばらつきがある。GitHub Copilot を活用して生産性・品質を向上させたい。
- **取り組み1: AIレビュー** — コーディング規約、仕様書チェックリスト、リソース観点などを与え、どの観点で何が問題かを根拠付きで回答させる。
- **取り組み2: UIレビュー／テンプレート横展開** — 製品ごとにバラついたUIを、既存アプリのUIスタイル（HTML/CSS）を抽出しルール化して他画面へ適用。
- **取り組み3: エージェントによるデバッグ支援** — 組込み（Linux／カメラシステム）を対象に、コード修正→ビルド→ターゲットへの書込み→ログ取得→デバッグのループをAIに回させる。WSL内のコンテナに閉じた環境を渡し、VS Code から接続。各工程で人が内容を確認してから実行。
- **現状評価（約半年）**: アウトプットの精度が向上、レビュー等で実用レベル。指示は「スキル」として資産化し横展開可能。今後は適用範囲（機能テスト等）拡大とプロセス整備が課題。

**CRA向け暗号ライブラリ検証（wolfSSL）**
- 暗号通信・証明書検証等で暗号ライブラリが必須。OpenSSL はメジャーだが脆弱性追従負荷とサイズが課題。小規模マイコン向けに **mbedTLS / wolfSSL** を比較し、wolfSSL を検証。
- **ターゲット**: ICC開発中のセンサーユニット（STマイコン、Cortex-M系32bit、100MHz程度、ROM約400KB／RAM約500KB、FreeRTOS、自作HTTPサーバ）。
- **結果（ROMサイズ）**: 一通りの機能を入れて **約200KB** に収まった。OpenSSL はビルド自体が入らず比較不可。ハッシュ／暗号化／公開鍵の機能別サイズも計測。
- **結果（性能）**: Wireshark のパケットキャプチャで計測。**TLSハンドシェイク約500ms以内**、以降の通信は**約150ms**程度で、簡易な設定画面用途としては実用レベル。
- **結論**: この規模のマイコンでも簡易HTTPS化は現実的。ライセンスはプロジェクト単位でイニシャルコスト中心。現在、MPCブロックのCRA対応に採用して組込み中（HTTPS優先、既存UDP通信やセキュアブートも検討）。

### ⑤ R&D：AI活用タスク管理と生成AI利用監視

**(1) AIを活用したタスク管理**
- **課題**: タスクの情報源がGitHub、Excel等に分散し、確認漏れ・優先順位付けの負担・判断のブレが発生。
- **対応**: 開発支援エージェント向けの**スキル群**を整備。情報源を横断して自動収集し、タスク管理表として整理、レポートを自動生成。レビュー用スキル、複雑なスキルを分解するスキルなども作成。
- **成果**: 情報収集作業が削減、見落としがなくなり、優先順位判断のブレが解消。今日やるべきアクションの推奨も提示。
- タスク管理表は**カンバン方式**をベースにAIがHTML生成（表示は閲覧のみ。状態変更はAIに「完了です」と伝えると次回生成時に反映）。

**(2) 生成AI利用状況の監視**
- **課題**: AWS（Amazon Bedrock）の利用情報は粒度が粗く（月単位等）、誰がどれだけ使っているか、いつ急増したかが見えない。Amazon Bedrock の不正利用に関する注意喚起もあり、リアルタイム把握が必要。
- **対応**: Bedrock の利用ログを自動解析・DB化し、利用状況を可視化する仕組みを構築。
  - 利用者ごとの月別／日別の累積コストを可視化。
  - 閾値超過時に利用者本人および管理者へ**自動通知**（プッシュ）。
- 一部事業部にはR&Dから既に共有済み。希望があれば展開可能。

### ⑥ ステアリング報告（GitHub / Copilot ライセンス・その他）
- GitHubが**従量課金制**に移行。契約は**4月更新**（対象期間は10月〜翌9月ベースの説明あり）。IT室から各Organization管理者へ来年度の利用予測の照会が届く。費用は各Organizationの予算で負担、必要に応じ稟議。
- **シート課金**: 1シート **$19**。10人分なら$190。シート数×$19分のAIクレジットが付与されるため、**実利用人数よりシート数を多めに確保**することでクレジットを確保する運用も可能。予算をシート単価で割ってシート数を手配する考え方。
- 超過分は**月払いで後日請求**。どのOrganizationが超過したかを確認して請求を割り当てる。
- **課題（実運用の問題）**: 8月にコストセンターを設定したが、**上限に達しても実際にはCopilotが使え続け、無料枠・他予算を消費してしまう**。表示だけが止まり、実質的な停止ができない。個人設定では停止したが、コストセンター単位では効かない。Organization単位での挙動は未検証で、今後確認予定。
- **Copilotライセンス追加の前提**: GitHubライセンスを保有しているユーザーにしかCopilotを割り当てられない点に注意。
- **その他案内**
  - Claude Code を試用したい人向けに、期間を区切って解放予定。
  - OSS関連の案内: 9月12日締切。
  - スキル調査（木下氏より連絡済み）: 12月25日まで、2年に1回実施。
  - **全社ソフトウェア研修**: 集合コース24〜67コース＋eラーニング。6名以上で開催。延べ58名参加、eラーニング33名。費用計 約621万円を人数割で各事業部へ請求。日額換算は従来コース3万円程度、新規コースは6万円程度。

## 3. 質疑応答まとめ

| # | 質問 / コメント | 回答 |
|---|---|---|
| Q1 | AI活用で「品質の上げ方を教育するのに一番役立った」とのことだが、実際に工数は早く終わるようになったのか？ | 定量的には測定していない。**むしろ分析結果を自分で読み込む、設計資料まで遡って直すなど、初期は時間がかかっている**体感。ただし周辺不具合は減っており、品質面・教育面での効果が大きい。「導入しなかった世界」が測れないのが悩み。 |
| Q2 | cgroup でメモリ上限に達したら、解放していく必要があるのでは？ | その通り。溜め込まない運用が必要。数十万〜百万ファイル規模を保持するような使い方もあるため、そこは検討課題。4GB全体を固定で使う必要があるシステムではない。 |
| Q3 | 回収はカーネルに任せるのか、対象プロセスを指定できるのか？ グループごとの優先度設定は可能か？ | cgroup 単位でグループ化でき、グループごとの優先度設定も可能。**今回はファイルアクセス用に1グループのみ**で運用している。 |
| Q4 | .NET/C# をLinux上で動かしている場合（ICC）、GCに任せている部分との兼ね合いは？ | 該当箇所は把握しづらい部分があり、担当者からフィードバックをもらう形とする。 |
| Q5 | AIレビューで使う「ドメイン知識／製品固有ルール」はどう与えるのか？ | まずは言語のコーディング規約に沿っているかの確認から着手。ルールは事前に**Markdown化**しておき、毎回参照させる方式。 |
| Q6 | 毎回ルールを食わせるとトークン消費が増えないか？ | 増える。「使うと3日でリミットに達する」という声があり、増枠要望が常時ある。現状は状況を見ながら部内で融通し、月ごとの配分を調整して運用している。 |
| Q7 | CRA対策13項目のうち、ソフトを新規に作り込む必要があるのはどれか？ | **上位2つ（①ログイン失敗時のアカウントロックアウト、②ネットワークモニタリング）**。①は認証部分で失敗回数を可視化すれば対応可。②は通信量に閾値を設けて遮断する方式を検討中で、実際の通信量計測が必要。暗号関連はライブラリ導入で対応可能だが、**証明書・鍵の管理方法の検討がややこしい**（生成方法、保管場所、鍵漏洩時の対応、可用性とのバランス）。 |
| Q8 | クラウド（AWS）側の監視ログは？ | AWS側に一応の提供機能があり調査済み。定期的に取得して保管する必要がある点は認識済み。全社コンサルにも確認中。 |
| Q9 | ボックスPC導入は顧客先での置き換え作業が発生するのでは？ | 発生する。トルコで約80顧客先あり、「1ヶ月かかる」と言われている。**CRA第14条の開始時期から逆算して8ヶ月以上前に準備着手**が必要。まずシステム構成確認と、業者を使ったセキュリティテスト・動作確認を実施予定。 |
| Q10 | UIテンプレート適用は、フレームワークが同じでないと難しいのでは？ Windows Formsのようなレガシーなデザイン手法では？ | 構成の理解しやすさに依存する。**HTML/スタイルシート系のほうが情報量が豊富でうまくいく**と思われる。Windows Forms 等は難しい可能性がある。 |
| Q11 | デバッグ支援エージェントで「工程ごとに人間が承認」しているが、工程によって人がチェックすべき重みは違うのでは？ | **ログの調査結果と修正方針のアプローチは人がきちんと確認すべき**。特にLinuxのログは「よくあるパターン」に流されやすく、全体を把握していないAIは"それっぽい解決策"に引きずられて無限ループに陥る。方針が外れていないかを人が見ることが重要。前提条件の与え方にも工夫の余地がある。放置すると収拾がつかなくなり、トークンを無駄に消費する。 |
| Q12 | タスク管理表のHTML上でタスク操作（To Do→In Progress→Done）はできるか？ | **HTMLは閲覧のみ**。ステータス変更は生成AIに「完了です」と伝えれば、次回の管理表生成時に反映される。 |
| Q13 | 他事業部の余ったCopilotクレジットを融通できるか？ | 完全に**Organization単位の支払い**に変わったため原則不可。$19を使い切らない人を多く抱えるOrganizationがあっても、個別対応（エンタープライズ側での追加調整）となる。 |
| Q14 | コストセンターに個人ではなくOrganizationを設定すると効かないのか？ | 効かない。権限の問題があり、別のやり方を検討中。改めて整理して共有する。 |
