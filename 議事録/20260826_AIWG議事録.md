## 4. 議事内容

### 4.1 全体

- **議事録の運用**
  - 本WGの議事録を残し、共有する運用とする。

- **ローカルLLMの動向ウォッチ**
  - ムラシスがローカルLLMを立ち上げた。社内GPUサーバを間借りし、Qwen3系コーディングモデル等を構築。
  - LiteLLMゲートウェイ経由で VS Code / GitHub Copilot Chat から利用可能。
  - 秘匿情報を外に出さずに使える／オフライン開発端末やライセンス非保有者でも利用可の見込み。現在10名程度が使用中。
  - クラウドの高性能モデル（Claude Opus 等）と併用・使い分けを想定。
  - **本WGとしては仕様・利用状況をウォッチし、情報側にFB（フィードバック）する。**

- **グランプリ（AIグランプリ）について**
  - グランプリのネタは各グループで決めなければいけない。
  - **対象は「製品に搭載するAI」**となっている模様（技術部門は製品搭載テーマ、業務側は業務改善テーマ）。
  - 製品に搭載するAIは各グループで決めてグランプリに出す。
  - **⇒ その「製品に搭載するAIを決めて開発するプロセス」を本WGで共通化できるか検討する。**
  - **⇒ 何を、どうやって搭載するかをWGで共有する。**
  - 期限感：8月中にテーマ選定、3月に報告。
  - ICCテーマとの重複については「出してよい」と確認済み。

- **機能仕様書**
  - 第3グループのサンプルも含めて検証していく。

- **GitHub利用に関する補足（環境・コスト）**
  - リポジトリ構成は「手順書／テンプレート／リファレンス／インプット／アウトプット」を想定。
  - リファレンスは過去成果物の"中身"ではなく、**形式・粒度（USDMの書き方、トレーサビリティの持ち方）** を参照させる用途。類似機種に限らない。
  - GitHubのUI経由ではExcelがフィルタで弾かれ、モデル（Opus）に読ませられない制約あり。最終成果物がExcelのため要検討。
  - GitHub CopilotはLLMごとにクレジット単価が異なる。1アカウント月19ドル、管理者側で上限設定・予算追加が可能。

- **情報共有体制**
  - 発信はしているが部門内で回りきっていない。チャンネルを整備し、最低限の情報共有を徹底する。
  - 第2G／電装ソフトからもリモートで構わないので参加し、情報を取ってほしい。

### 4.3 第2グループ — 納入仕様書まわりの課題（本日の中心議論）

- **課題リストの網羅性が担保できない**
  - 納入仕様書から課題リスト（「変えないといけない」ということだけが分かるもの）はできるが、**網羅性がない**。
  - 具体的に不足するのは「どう変えるか」「どこを・どこまで変えるか」「変える場所が網羅できているのか」。
  - 画面仕様書の変化点はSEが作成しており、**属人的に網羅している**状態。「網羅しているであろうもの」ができる。

- **確認工程も属人的**
  - 納入仕様書（SEが属人的に作成）どおりに動いているかの確認もSEが実施。**そこが一番属人的。**

- **モデル設計**
  - お客さんが利用しているデータを扱うモデルを設計する（有識者で決めている）。

- **手戻りを減らすアプローチ**
  - まずはお客さんを含めず、**社内で戻りの内容にするほうがいい**。
  - SEが要求を伝えた後で、さらに新しい要求が発生するのが手戻りの主因。

- **AI活用の狙い**
  - **GMISをAIに食わせる → 課題リストを食わせる → 画面仕様書（要求機能仕様書）の変化点を出す。**
  - **変化点が完璧であれば品質は大丈夫。**
  - 工数は出せるのか ⇒ **出せる。**
